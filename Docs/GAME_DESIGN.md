## 1. 프로젝트 개요

### 1.1 게임 한 줄 소개

> 숫자 블록을 빠르게 연결해 목표 합을 만들고, 연속 정답으로 피버를 발동해 망가진 공간을 시원하게 복구하는 캐주얼 퍼즐 게임.

### 1.2 핵심 콘셉트

MathGame은 보드에 배치된 숫자 블록을 상하좌우로 연결하여 목표 숫자를 만드는 게임이다.

플레이어는 충분히 생각하면서 퍼즐을 풀 수 있지만, 빠르게 정답을 완성할수록 `PERFECT` 또는 `FAST` 판정을 받고 피버 게이지를 더 많이 획득한다.

피버가 발동하면 블록 제거 범위와 장애물 피해가 증가하고, 배경 공간이 빠르게 복구된다.

### 1.3 핵심 재미

- 목표 숫자를 만드는 조합을 발견하는 재미
- 짧고 빠르게 정답을 완성하는 순발력
- 긴 숫자 조합을 찾아 강력한 효과를 만드는 전략
- 연속 정답으로 피버를 발동하는 긴장감
- 블록과 장애물을 한꺼번에 제거하는 폭발감
- 오염되고 망가진 공간이 깨끗하게 변하는 시각적 성취감

### 1.4 핵심 차별점

일반적인 계산 게임은 정답 선택과 기록 경쟁에 집중하고, 일반적인 연결 퍼즐은 같은 색이나 같은 모양을 연결한다.

MathGame은 다음 세 가지를 결합한다.

> 숫자 조합 탐색 + 빠른 계산 보상 + 공간 복구

속도는 스테이지 성공 조건이 아니라 추가 보상을 얻는 플레이 방식으로 사용한다. 따라서 느린 플레이어도 정상적으로 게임을 진행할 수 있고, 숙련자는 빠른 계산으로 더 강한 보상을 경험할 수 있다.

## 2. 목표 사용자

### 2.1 핵심 타깃

- 만 15~45세 캐주얼 퍼즐 이용자
- 짧은 시간에 플레이할 게임을 원하는 사용자
- 블록 제거와 폭발 연출을 선호하는 사용자
- 숫자 퍼즐은 좋아하지만 학습 게임처럼 느껴지는 게임은 부담스러운 사용자
- 공간 꾸미기와 복구형 메타 콘텐츠를 선호하는 사용자

### 2.2 플레이 상황

- 출퇴근 및 등하교 시간
- 대기 시간
- 취침 전
- 3~10분 정도의 짧은 휴식
- 인터넷 연결이 불안정한 환경

### 2.3 지향하는 감정

- “이 조합이 바로 보였다.”
- “이번에는 정말 빠르게 풀었다.”
- “한 번 더 맞히면 피버다.”
- “피버로 보드가 전부 터졌다.”
- “망가진 공간이 눈에 띄게 깨끗해졌다.”

### 2.4 지양하는 인상

- 수학 시험
- 학습지
- 암산 훈련 프로그램
- 시간제한에 계속 쫓기는 스트레스
- 광고 시청을 강요하는 게임
- 계산보다 운에 의존하는 퍼즐

## 3. 핵심 게임 흐름

### 3.1 전체 플레이 흐름

1. 복구할 공간과 스테이지를 선택한다.
2. 목표 숫자를 확인한다.
3. 보드의 숫자 블록을 상하좌우로 연결한다.
4. 연결한 숫자의 합이 목표값과 같으면 정답 처리된다.
5. 선택한 숫자 블록이 제거되고 새로운 블록이 낙하한다.
6. 정답 속도와 연결 길이에 따라 피버 게이지를 획득한다.
7. 피버를 발동해 장애물과 블록을 대량 제거한다.
8. 제한 행동 횟수 안에 스테이지 목표를 달성한다.
9. 획득한 복구 에너지로 공간을 복구한다.
10. 다음 스테이지와 복구 구역을 개방한다.

### 3.2 핵심 반복 구조

> 목표 확인 → 숫자 연결 → 정답 판정 → 블록 제거 → 낙하 → 피버 충전 → 피버 발동 → 장애물 제거 → 공간 복구

### 3.3 세션 길이

| **구분**    | **목표 시간** |
| --------- | --------- |
| 튜토리얼 스테이지 | 1~2분     |
| 일반 스테이지   | 2~4분     |
| 어려운 스테이지  | 4~6분     |
| 1회 접속 플레이 | 5~15분    |

## 4. 기본 퍼즐 규칙

### 4.1 보드 규격

프로토타입의 기본 보드는 `5×5`로 구성한다.

테스트 결과에 따라 다음 규격을 비교할 수 있다.

- 5×5: 조합 탐색이 쉽고 모바일 가독성이 높음
- 6×6: 조합이 다양하지만 화면이 복잡해질 가능성이 있음

MVP 기본값은 5×5로 설정한다.

### 4.2 숫자 블록

초기 숫자 범위는 `1~9`로 설정한다.

- 숫자는 양의 정수만 사용한다.
- 동일한 숫자가 여러 개 등장할 수 있다.
- 숫자별 색상을 다르게 사용할 수 있지만, 색상이 숫자의 의미를 대신하지 않는다.
- 숫자는 항상 텍스트로 명확하게 표시한다.

### 4.3 연결 방법

- 손가락을 누른 상태로 숫자 블록을 드래그한다.
- 상하좌우로 인접한 블록만 연결할 수 있다.
- 대각선 연결은 허용하지 않는다.
- 이미 선택한 블록은 같은 연결 안에서 다시 선택할 수 없다.
- 빈칸이나 장애물을 통과할 수 없다.
- 손가락을 떼면 현재 조합을 확정한다.
- 시작 블록으로 되돌아가거나 직전 블록을 역방향으로 지나가면 마지막 선택을 취소할 수 있다.

### 4.4 연산 규칙

MVP는 덧셈만 사용한다.

예시:

- 목표 `10`: `4 + 6`
- 목표 `10`: `2 + 3 + 5`
- 목표 `10`: `1 + 2 + 3 + 4`

선택 중인 숫자는 화면 상단에 실시간 수식으로 표시한다.

목표 10



2 + 3 + 5 = 10

### 4.5 정답 판정

선택한 숫자의 합이 목표값과 같으면 정답이다.

- 합이 목표보다 작은 경우: 선택 유지
- 합이 목표와 같은 경우: 정답 가능 상태 표시
- 합이 목표를 초과한 경우: 연결선 경고 표시
- 목표를 초과한 상태에서 손을 떼면 오답 처리
- 정답 상태가 되더라도 손을 떼기 전까지 추가 연결 가능
- 추가 연결로 목표를 초과하면 다시 오답 상태가 됨

정답 상태에서는 연결선과 숫자 블록에 명확한 강조 효과를 적용한다.

### 4.6 오답 처리

- 행동 횟수를 차감하지 않는다.
- 선택한 블록은 제거되지 않는다.
- FAST 연속 기록을 초기화한다.
- 피버 게이지 전체는 초기화하지 않는다.
- 짧은 흔들림과 낮은 강도의 피드백만 제공한다.
- 부정적인 실패 문구나 강한 경고음은 사용하지 않는다.

오답을 반복하는 경우 정답을 직접 보여주기보다는 가능한 시작 블록 하나를 약하게 강조한다.

## 5. 목표 숫자 시스템

### 5.1 목표 숫자 범위

초기 스테이지의 목표 숫자는 `5~10`으로 설정한다.

진행에 따라 다음과 같이 확장한다.

| **구간**  | **목표 숫자 예시**    |
| ------- | --------------- |
| 초반      | 5~10           |
| 중반      | 8~15           |
| 후반      | 10~20          |
| 특수 스테이지 | 지정된 목표 또는 연속 목표 |

### 5.2 목표 생성 원칙

목표 숫자는 완전히 무작위로 선택하지 않는다.

다음 조건을 만족하는 목표만 제시한다.

- 현재 보드에 최소 1개 이상의 정답 경로가 존재
- 상하좌우 연결만으로 완성 가능
- 잠긴 블록이나 제거 불가능한 장애물을 통과하지 않음
- 초반에는 2~3개 블록 조합이 최소 1개 존재
- 진행에 따라 4개 이상의 긴 조합도 유도

### 5.3 목표 전환

정답 처리와 블록 낙하가 완료되면 다음 목표가 표시된다.

- 목표 전환 연출은 0.5초 이내로 구성
- 목표가 표시되고 조작 가능 상태가 된 순간부터 판정 시간 측정
- 전환 중에는 플레이어 입력을 받지 않음
- 동일한 목표 숫자가 연속 등장하는 빈도를 제한

### 5.4 교착 상태 처리

현재 목표를 만들 수 있는 조합이 없으면 다음 순서로 처리한다.

1. 조합 탐색 알고리즘으로 실제 정답 존재 여부를 검사한다.
2. 정답이 없다면 목표 숫자를 다시 생성한다.
3. 가능한 목표가 없다면 보드를 자동 셔플한다.
4. 자동 처리로 플레이어의 행동 횟수는 차감하지 않는다.

## 6. 연결 길이 보상

같은 목표 숫자를 만들더라도 더 많은 블록을 연결하면 강한 보상을 제공한다.

| **연결 블록 수** | **기본 결과**            |
| ----------- | -------------------- |
| 2개          | 선택 블록 제거             |
| 3개          | 피버 게이지 추가 획득         |
| 4개          | 특수 블록 생성             |
| 5개 이상       | 광역 제거 또는 강화 특수 블록 생성 |

### 6.1 설계 목적

- 가장 쉬운 2개 조합만 반복하는 문제 방지
- 보드를 자세히 관찰하도록 유도
- 빠른 짧은 조합과 느린 긴 조합 사이에 선택 제공
- 연결 퍼즐 특유의 발견과 계획 재미 강화

### 6.2 선택의 구조

플레이어는 상황에 따라 두 가지 전략을 선택할 수 있다.

- 짧은 조합을 빠르게 완성해 FAST 판정 획득
- 긴 조합을 만들어 특수 블록과 추가 게이지 획득

두 방식 모두 유효하도록 속도 보상과 연결 길이 보상을 분리한다.

## 7. 특수 블록

### 7.1 기본 특수 블록

| **특수 블록** | **생성 조건** | **효과**             |
| --------- | --------- | ------------------ |
| 가로 폭탄     | 4개 연결     | 가로 한 줄 제거          |
| 세로 폭탄     | 4개 연결     | 세로 한 줄 제거          |
| 범위 폭탄     | 5개 이상 연결  | 주변 일정 범위 제거        |
| 무지개 숫자    | 특수 조건     | 선택한 조합에 필요한 숫자를 보충 |

### 7.2 특수 블록 발동

- 특수 블록을 숫자 조합에 포함하면 정답 처리 후 발동
- 특수 블록 자체의 숫자값은 블록에 표시된 값을 사용
- 특수 블록끼리 인접 폭발이 발생할 수 있음
- 연쇄 폭발 중에는 피버 시간이 감소하지 않음

### 7.3 MVP 범위

초기 프로토타입에서는 특수 블록 종류를 최소화한다.

- 4개 연결: 가로 또는 세로 폭탄
- 5개 이상 연결: 범위 폭탄

무지개 숫자와 특수 블록 조합 효과는 MVP 이후 검토한다.

## 8. 행동 횟수와 스테이지 조건

### 8.1 행동 횟수

스테이지마다 제한 행동 횟수가 제공된다.

- 정답을 완성하면 행동 횟수 1회 차감
- 오답은 행동 횟수 미차감
- 피버 중 정답은 행동 횟수 미차감
- 특수 블록의 연쇄 폭발은 추가 행동으로 계산하지 않음

### 8.2 성공 조건

스테이지마다 한 가지 이상의 목표를 제공할 수 있다.

- 특정 장애물 제거
- 지정 개수의 숫자 블록 제거
- 복구 에너지 획득
- 특정 목표 숫자 완성
- 지정 횟수 이상 긴 조합 완성
- 특수 블록 생성 및 사용

초반에는 한 가지 목표만 제공하고, 중반부터 최대 두 가지 조건을 조합한다.

### 8.3 실패 조건

행동 횟수를 모두 사용했지만 목표를 달성하지 못하면 실패한다.

실패 화면에서는 다음 정보를 제공한다.

- 남은 목표
- 부족했던 수량
- 이어하기
- 재도전
- 스테이지 나가기

### 8.4 이어하기

보상형 광고를 시청하면 추가 행동 횟수를 제공한다.

초기 기준:

- 광고 1회 시청
- 추가 행동 5회
- 스테이지당 1회 사용 가능

실제 수치는 플레이 데이터와 광고 수익성을 바탕으로 조정한다.

## 9. 피버 시스템

### 9.1 목적

피버는 빠르게 정답을 발견한 플레이어에게 강력한 보상을 제공하는 핵심 시스템이다.

기본 퍼즐에서는 충분히 생각할 수 있게 하되, 빠른 계산과 연속 정답을 통해 더 큰 폭발과 공간 복구를 경험하게 한다.

> 빠른 숫자 연결 → FAST 연속 성공 → 피버 발동 → 연속 폭발 → 장애물 제거 → 공간 대규모 복구

### 9.2 시간 판정

시간은 새로운 목표가 표시되고 플레이어가 조작할 수 있게 된 순간부터 측정한다.

| **완료 시간** | **판정**  | **기본 게이지** |
| --------- | ------- | ---------- |
| 2초 이내     | PERFECT | +25        |
| 4초 이내     | FAST    | +15        |
| 4초 초과     | NORMAL  | +5         |
| 오답        | MISS    | 없음         |

초기값은 프로토타입 검증용이며 테스트 후 조정한다.

### 9.3 시간 측정에서 제외되는 구간

- 블록 제거
- 신규 블록 낙하
- 장애물 파괴
- 목표 숫자 전환
- 특수 블록 연쇄 폭발
- 피버 시작과 종료 연출
- 일시정지
- 앱 비활성화
- 광고 재생

### 9.4 게이지 충전

피버 게이지 최대치는 `100`이다.

| **조건**     | **추가 충전량** |
| ---------- | ---------- |
| PERFECT    | +25        |
| FAST       | +15        |
| NORMAL     | +5         |
| 3개 연결      | +3         |
| 4개 연결      | +6         |
| 5개 이상 연결   | +10        |
| FAST 2연속부터 | 회당 +5      |

예시:

1.8초 안에 숫자 4개 연결

PERFECT +25

연결 길이 보너스 +6

총 피버 게이지 +31

### 9.5 피버 발동

피버 게이지가 100에 도달하면 다음 조건에서 발동한다.

- 현재 정답 처리가 완료됨
- 블록 제거와 낙하가 완료됨
- 스테이지 성공 또는 실패가 확정되지 않음
- 플레이어가 정상적으로 조작할 수 있는 상태

약 0.5초의 짧은 전환 연출 후 바로 플레이를 재개한다.

### 9.6 지속시간

기본 피버 지속시간은 `8초`다.

피버 시간은 플레이어가 실제로 조작할 수 있을 때만 감소한다.

### 9.7 피버 효과

| **요소** | **일반 상태** | **피버 상태**       |
| ------ | --------- | --------------- |
| 행동 횟수  | 정답당 1회 소모 | 소모하지 않음         |
| 블록 제거  | 선택 블록 제거  | 선택 블록과 주변 블록 제거 |
| 장애물 피해 | 1배        | 2배              |
| 공간 복구량 | 기본값       | 2배              |
| 점수     | 기본 배율     | 콤보 배율 적용        |
| 연출     | 기본 효과     | 강화 파티클·사운드·진동   |

피버 중 오답을 선택해도 피버는 종료되지 않는다. 피버 콤보와 배율만 초기화한다.

### 9.8 피버 콤보

| **피버 중 연속 정답** | **배율** |
| -------------- | ------ |
| 1회             | ×1     |
| 2회             | ×2     |
| 3회             | ×3     |
| 4회 이상          | ×5     |

배율 적용 대상:

- 점수
- 공간 복구 에너지
- 종료 폭발 강도
- 시각·사운드 연출 단계

장애물 피해는 최대 2배로 제한한다.

### 9.9 피버 종료 효과

| **피버 중 정답 횟수** | **종료 효과**      |
| -------------- | -------------- |
| 0회             | 추가 효과 없음       |
| 1회             | 무작위 블록 3개 제거   |
| 2회             | 작은 범위 폭발       |
| 3회             | 보드 중앙 범위 폭발    |
| 4회 이상          | 대규모 폭발 및 복구 연출 |

피버 종료 후 게이지는 0으로 초기화한다.

### 9.10 스트레스 방지 원칙

- FAST 실패는 스테이지 실패가 아님
- NORMAL도 소량의 피버 게이지 제공
- 오답으로 행동 횟수는 차감하지 않음
- 오답으로 피버 게이지 전체를 잃지 않음
- 느린 플레이어도 모든 스테이지를 클리어할 수 있음
- 빠른 계산은 필수가 아닌 숙련 보상으로 설계

## 10. 장애물 시스템

### 10.1 장애물 종류

| **장애물** | **기본 규칙**        | **피버 효과**       |
| ------- | ---------------- | --------------- |
| 먼지      | 인접 정답으로 제거       | 제거 범위 증가        |
| 상자      | 인접 정답 2회 필요      | 한 번에 2 피해       |
| 얼음      | 내부 숫자 사용 후 얼음 제거 | 얼음과 블록 동시 제거 가능 |
| 잠금      | 조건 달성 전 선택 불가    | 해제 충전량 2배       |
| 고정 블록   | 낙하하지 않음          | 피해량 증가          |
| 오염 타일   | 위의 숫자 제거 시 정화    | 주변 오염까지 정화      |

### 10.2 장애물 배치 원칙

- 정답 경로를 완전히 차단하지 않는다.
- 장애물이 있어도 최소 1개 이상의 정답이 존재해야 한다.
- 초반에는 한 종류의 장애물만 사용한다.
- 장애물 추가 전 안전한 환경에서 규칙을 학습시킨다.
- 피버를 사용하면 분명하게 유리해지도록 배치한다.

## 11. 공간 복구 시스템

### 11.1 콘셉트

플레이어는 퍼즐을 해결하면서 오염되고 망가진 공간을 복구한다.

공간 복구는 스테이지 선택 화면에만 존재하는 별도 기능이 아니라 퍼즐 플레이 중에도 실시간으로 표현한다.

### 11.2 복구 단계

하나의 공간은 여러 복구 단계로 구성된다.

1. 먼지와 쓰레기 제거
2. 벽과 바닥 수리
3. 조명 복구
4. 가구 복구
5. 장식 배치
6. 공간 완성

### 11.3 복구 에너지

정답을 완성하면 복구 에너지를 획득한다.

기본 복구량

× 연결 길이 보너스

× 피버 배율

- 일반 정답: 기본 복구량
- 긴 조합: 추가 복구량
- 피버 정답: 복구량 증가
- 피버 종료 폭발: 추가 복구 에너지

### 11.4 실시간 변화

퍼즐 플레이 중 다음 변화가 배경에 반영된다.

- 먼지가 사라짐
- 어두운 조명이 켜짐
- 벽의 균열이 복구됨
- 파손된 가구가 단계적으로 복원됨
- 공간의 채도와 밝기가 증가함

### 11.5 선택형 꾸미기

MVP에서는 복구 결과를 고정한다.

출시 이후 확장 기능으로 다음을 고려한다.

- 가구 디자인 선택
- 벽지 및 바닥 선택
- 테마별 장식
- 시즌 한정 복구 공간
- 완료 공간 재방문 및 촬영

## 12. 스테이지 진행

### 12.1 월드 구조

하나의 월드는 하나의 공간 복구 테마를 가진다.

예시:

| **월드** | **공간**  |
| ------ | ------- |
| 1      | 낡은 원룸   |
| 2      | 버려진 카페  |
| 3      | 오래된 정원  |
| 4      | 폐쇄된 도서관 |
| 5      | 해변 상점   |

### 12.2 난이도 상승 요소

- 목표 숫자 범위 증가
- 사용 가능한 정답 조합 감소
- 장애물 종류 증가
- 장애물 내구도 증가
- 복수의 스테이지 목표
- 제한 행동 횟수 감소
- 특수한 보드 형태
- 숫자 생성 확률 변화

### 12.3 난이도 원칙

난이도는 계산식 자체보다 보드 구조와 선택의 우선순위로 조절한다.

복잡한 암산을 강요하기보다 다음 판단을 요구한다.

- 어떤 조합을 먼저 제거할 것인가?
- 빠른 짧은 조합과 긴 조합 중 무엇을 선택할 것인가?
- 피버를 언제 발동시킬 것인가?
- 어떤 장애물부터 제거할 것인가?

## 14. UI 구성

### 14.1 퍼즐 화면

상단 영역:

- 남은 행동 횟수
- 스테이지 목표
- 목표 숫자
- 선택 중인 수식
- 피버 게이지
- 일시정지 버튼

중앙 영역:

- 숫자 퍼즐 보드
- 장애물
- 연결선
- 정답 및 폭발 연출

하단 또는 보드 주변:

- 부스터
- 공간 복구 진행 상태
- 피버 중 현재 배율과 남은 시간

### 14.2 판정 UI

표시 예시:

PERFECT! 1.8초

FAST! 3연속

NORMAL

FEVER ×3

- 색상만으로 상태를 구분하지 않는다.
- 문자, 아이콘, 효과를 함께 사용한다.
- FAST 판정은 짧고 명확하게 표시한다.
- NORMAL은 실패처럼 보이지 않도록 차분하게 표시한다.

### 14.3 연결선

- 선택 순서를 명확하게 보여준다.
- 정답 가능 상태에서는 밝게 강조한다.
- 목표 초과 시 붉은색 또는 경고 패턴을 표시한다.
- 장애물과 겹치지 않는다.
- 손가락에 가려지는 문제를 줄이기 위해 선택 숫자를 상단 수식으로 동시에 표시한다.

## 18. 수익 모델

### 18.1 기본 방향

보상형 광고를 주 수익원으로 사용하고 전면 광고와 광고 제거 상품을 결합한다.

단기적인 광고 노출 극대화보다 리텐션을 해치지 않는 범위에서 `ARPDAU`, `LTV`, 광고 참여율을 검증한다.

### 18.2 보상형 광고

사용 위치:

- 실패 후 행동 횟수 추가
- 스테이지 시작 전 부스터 획득
- 클리어 보상 2배
- 무료 부스터 획득
- 피버 게이지 일부 충전

광고를 시청하지 않아도 기본 진행이 가능해야 한다.

### 18.3 전면 광고

초기 기준:

- 스테이지 클리어 직후 매번 노출하지 않음
- 일정 스테이지 이상 진행 후 활성화
- 최소 노출 간격 적용
- 실패 직후에는 원칙적으로 노출하지 않음
- 보상형 광고 시청 직후 전면 광고 금지
- 첫 세션과 튜토리얼 구간 노출 금지

### 18.4 인앱 결제

초기 상품:

- 광고 제거
- 광고 제거 + 소량의 부스터 패키지
- 스타터 패키지

광고 제거 상품은 강제 광고를 제거하되, 보상형 광고는 사용자가 선택할 수 있게 유지하는 방식을 검토한다.

## 28. 최종 게임 방향

MathGame은 정답을 빠르게 맞히는 단순 계산 게임도 아니고, 숫자만 사용한 일반적인 연결 퍼즐도 아니다.

플레이어는 보드를 관찰해 목표 숫자를 만들고, 빠른 판단과 긴 조합 사이에서 전략을 선택한다. 빠른 연속 정답은 피버로 연결되고, 피버는 보드 폭발과 공간 복구라는 강력한 보상으로 돌아온다.

최종 핵심 재미는 다음과 같이 정의한다.

> **빠르게 숫자 조합을 발견하고, 연속 정답으로 피버를 발동해 보드와 망가진 공간을 한꺼번에 복구하는 쾌감**
# Production Addendum — Continuous Run Speed Survival (2026-08-15)

This addendum overrides the finite Stage loop only for the primary Production gameplay mode. Legacy Stage mode remains available for compatibility and does not define Continuous Run behavior.

- Primary Production gameplay is a continuous addition-only, orthogonal-connection survival run.
- Time is the sole primary survival resource. Moves and objectives do not end a Continuous Run.
- Time drains during every live, non-paused Run phase, including input, answer resolution, removal, gravity, refill, target updates, recovery, and Fever transitions. Legitimate pause/interruption stops both drain and active-duration accumulation.
- If time reaches zero before a correct answer commits, Run End wins. A correct answer already atomically committed before expiry observation may apply its recovery exactly once.
- Time capacity, initial time, drain rate, and Normal/Fast/Perfect recovery are configurable balance data. Recovery clamps to maximum capacity. Fever adds no extra time modifier.
- Difficulty advances by completed correct-answer cycles. The first migration changes only proven target difficulty/range at challenge boundaries; board number ranges, obstacles, and Fever rules do not scale yet.
- Every displayed target must retain a current legal witness. Correct resolution, gravity/refill, and safe-target recovery continue inside the same Run.
- Time reaching zero ends the Run exactly once, disables board input, freezes a result, and presents Play Again. No normal Stage Clear or Next Stage occurs in Continuous Run.
- Run Result survival duration is total active Run gameplay time, excluding paused/interrupted time.
- Existing Board, connection, answer grade, resolution, score, Fever, obstacle, and serialized BoardView behavior should be reused without transferring rule authority to UI.
